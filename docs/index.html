Retinal screening · MATLAB + Flask

Grade diabetic retinopathy from a single fundus photo.

One image goes in. An ICDR grade, a referral decision, an annotated lesion overlay, a Grad-CAM attention map and a patient-readable PDF come out — with the classical and neural paths cross-checking each other.

The pipeline

Five stages. Each one can be run and inspected on its own in MATLAB — the web layer is a wrapper, not the logic.

1

Quality gate

Hough-circle field-of-view detection, Laplacian-variance blur scoring and histogram exposure analysis sort every image into pass, enhanced (CLAHE + edge-preserving denoise) or reject. A rejected image stops here — no grade is guessed from a photo that can't support one.

assessImageQuality.m
2

Segmentation

Optic disc and fovea localisation, multi-orientation matched-filter vessel segmentation, top-hat microaneurysm detection, and background-subtraction exudate and haemorrhage segmentation — plus an experimental neovascularization proxy. All thresholds are fractions of the field-of-view radius, so the same settings transfer across cameras and resolutions.

segmentRetina.mdlSegmentVessels.m
3

Two independent graders, then consensus

One path applies the International Clinical DR scale directly, including the 4-2-1 rule for severe NPDR. The other fine-tunes an EfficientNet-B0 or ResNet-50 backbone, calibrates its confidence with Platt scaling, and picks a referral cut-off from the ROC curve. They only produce a grade when they agree; disagreement is flagged for human review.

gradeByRules.mtrainDRClassifier.mpredictDRGrade.mcalibrateConfidence.mtuneReferableThreshold.mcombineGrades.m
4

Explanation

A Grad-CAM map showing where the network actually looked, a colour-coded lesion overlay with labelled leader lines, quadrant-wise lesion counts, and a JSON + PNG export the web layer reads instead of parsing MATLAB structs.

gradCAMHeatmap.mdrawLesionOverlay.mexplainGrading.mcompileReportData.m
5

Delivery

A Flask app holds a persistent MATLAB Engine session so scans don't pay the 30-second startup cost each time, and generates a styled PDF report with plain-language prose an LLM writes — from a grade it is explicitly forbidden to change.

runDRPipelineProduction.mapp.pymatlab_bridge.pyreport_generator.py

Two runtime modes, selected automatically

The trained CNN is an enhancement, not a dependency. If the model file is missing, unreadable or untrained, the pipeline degrades to the rule-based path and reports which one it took — nothing crashes and no flag needs flipping.

real_full

A trained model loaded

  • CNN and rule grades combined through consensus
  • Grad-CAM attention map
  • Platt-calibrated confidence score
  • Colour-coded lesion overlay
  • Tuned referral threshold
real_no_cnn

Model missing or untrained

  • Rule-based ICDR grade from lesion counts
  • Colour-coded lesion overlay
  • No Grad-CAM
  • No confidence score
  • Full PDF report still generates

Design decisions

The interesting parts of this project are the places where the obvious choice was the wrong one.

Classical segmentation over a learned one

Matched filters and top-hat transforms rather than a segmentation network. Every decision is inspectable — orientation, scale, threshold — which matters more than raw accuracy when a clinician asks why a pixel was called a haemorrhage.

Calibrated confidence, not raw softmax

Networks are systematically overconfident. Platt scaling fitted on the validation split means a reported 80% actually corresponds to being right about 80% of the time — and expected calibration error is reported before and after.

Tuned for sensitivity, not accuracy

A missed referable case costs far more than a false alarm. The operating point is chosen for the best specificity among cut-offs that reach 90% sensitivity, rather than whatever maximises overall accuracy.

Disagreement is an output

When the CNN and the clinical rules diverge, the result isn't a tiebreak — it's a review flag with no grade, marked referable if either path says so. The safe default for screening.

The LLM never grades

Gemini writes the patient-facing paragraphs and nothing else. The grade is a fixed input it is forbidden to re-derive or contradict, and if the API is down the report still generates from canned neutral prose.

Weak parts are labelled weak

The neovascularization detector is documented in its own source as an experimental proxy that will fire on dense normal arcades. Naming a limitation is more useful than hiding it behind a confident number.

Stack

Analysis in MATLAB, delivery in Python, bridged by the MATLAB Engine.

Image analysis

  • MATLAB R2021a+
  • Image Processing Toolbox
  • Deep Learning Toolbox
  • Statistics & ML Toolbox
  • Computer Vision Toolbox (optional)

Models

  • EfficientNet-B0 / ResNet-50 transfer learning
  • Class-balanced sampling, augmentation
  • Quadratic weighted kappa evaluation
  • Grad-CAM attribution
  • Optional U-Net vessel path

Application

  • Flask + MATLAB Engine for Python
  • fpdf2 report layout
  • Gemini for patient-facing prose
  • JSON hand-off between layers
  • APTOS 2019 / IDRiD / Messidor-2 loaders

What this doesn't do

  • Neovascularization detection is a heuristic proxy, not a validated detector — it also fires on dense normal arcades and poor crops.
  • Haemorrhages are localised but not sub-typed into dot, blot or flame.
  • Venous beading and IRMA are accepted as inputs to the rule grader but aren't detected automatically, so two of the three severe-NPDR triggers need external input.
  • The shipped checkpoint is a short demo fine-tune on a subsampled dataset. It makes the real_full path runnable; it is not accurate enough to screen anyone.
  • The MATLAB Engine is a locked singleton, so scans are serialised — fine for a kiosk, not for concurrent load.
